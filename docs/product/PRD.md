## 2. 서비스 소개

### 2.1 배경 및 목적

대형 종합 여행사(노랑풍선, 하나투어 등 OTA)의 패키지 상품은 종류가 많고 구조가 복잡해 일반 고객이 자기 조건에 맞는 상품을 빠르게 찾기 어렵다. 일정·포함내역·출발확정 여부·동적 가격 등 비교 포인트가 많고 흩어져 있어 의사결정 비용이 크다.

Nextour는 이 복잡성을 **AI 시맨틱 검색 + 핵심 요약 + 구조화된 비교 UX**로 풀어, 패키지 여행을 직관적으로 탐색·예약할 수 있게 한다.

### 2.2 핵심 가치 제안

- **자연어로 묻고 답하는 탐색 경험**: "내년 3월 오사카 3박 4일, 숙소 좋고 쇼핑 없는 코스" 같은 문장 그대로 검색.
- **AI 3줄 요약**: 긴 일정표·약관을 스크롤하기 전에 장점/주의점을 먼저 본다.
- **여행사 도메인 규칙을 그대로 반영한 예약 플로우**: 최소 출발 인원, 동적 가격, 실시간 좌석 차감, 예약 접수→출발 확정→결제 완료의 단계적 상태 관리.

## 4. 주요 기능

### 4.1 핵심 기능 (MVP)

#### A. 메인 홈 & AI 검색
- [ ] **AI 시맨틱 검색바**: 문장형 입력이 가능한 넓은 입력창
- [ ] **추천 칩(Chip)**: "부모님 동반 온천 여행", "가성비 휴양지" 등 프리셋 태그
- [ ] **검색 결과 카드**: 상품명 / 썸네일 / 1인 기준 가격 / 기간(박·일) / 핵심 태그(#노쇼핑, #출발확정 …) / AI 추천 코멘트 한 줄

#### B. 상품 상세 페이지 (PDP)
- [ ] **AI 3줄 핵심 요약**: 상단에 장점·주의점 노출 (예: 가이드 경비 별도)
- [ ] **출발일/가격 달력**: 날짜별 성인·아동 요금, 잔여 좌석, 마감 임박 표시
- [ ] **포함/불포함 내역 분리 UI**: 탭 또는 박스로 시각적 완전 분리
- [ ] **일정표 타임라인**: N일 차별 방문지·식사·숙소를 시간 흐름으로 시각화

#### C. 예약 & 결제 퍼널
- [ ] **예약자 vs 실제 여행자 정보 분리**: 영문 성명/성별/생년월일 등 여권 정보 수집
- [ ] **필수 약관 동의**: 국외여행 표준약관 + 특별약관(취소 수수료 차등) 체크 로직
- [ ] **결제 상태 분리**: '예약 접수(대기)' 상태 존재 → 담당자 확정 후 최종 결제로 진행되는 안내 플로우
- [ ] **결제 정책**: 예약 접수 단계는 **무결제 대기**, 출발/모객 확정 후 **전액 결제** (예약금/잔금 분할 없음) — 결제 수단은 토스페이먼츠

#### D. 마이페이지
- [ ] **예약 상태 트래킹 (Progress Bar)**: 예약 접수 → 출발 대기(최소 인원 미달) → 출발 확정 → 결제 완료 → 여행 준비(E-ticket)

#### E. 도메인 핵심 비즈니스 정책 (시스템 반영 필수)
- [ ] **최소 출발 인원 시스템**: 미달 시 '출발 미정' 상태로 안내
- [ ] **동적 가격(Dynamic Pricing)**: 출발일/주중·주말/항공 스케줄별 가격 차등
- [ ] **재고(좌석) 실시간 차감**: 예약 진행 시점에 잔여석 즉시 차감하여 중복 예약 방지

#### F. 여행사 어드민 (MVP에 포함)
- [ ] **상품 관리**: 패키지 상품 등록·수정, 일정표·포함/불포함 내역 입력
- [ ] **출발일/가격 관리**: 출발일별 단가·최소 출발 인원·잔여 좌석 설정 (동적 가격)
- [ ] **예약 관리**: 접수된 예약 조회, 상태 변경(접수 → 출발 확정 → 결제 완료)
- [ ] **고객 정보 열람**: 여권 정보·약관 동의 기록
- [ ] **권한**: 어드민 계정은 별도 (단일 여행사 가정, 다중 테넌트 아님)

## 5. 기술 스택

| 분류 | 기술 | 비고 |
|------|------|------|
| Frontend | **Next.js (App Router) + TypeScript** | PDP SEO, 서버 컴포넌트로 초기 로딩 최적화 |
| Backend | **Next.js API Routes (Route Handlers)** | 별도 백엔드 없이 한 레포에서 운영 |
| ORM | **Prisma** | 스키마 우선, 마이그레이션 관리 |
| Database | **PostgreSQL** | 좌석 차감은 트랜잭션으로 동시성 처리 |
| Vector | **pgvector** (PostgreSQL extension) | 상품 임베딩 → 시맨틱 검색 |
| AI / LLM | **Anthropic Claude API** | 쿼리 해석, 3줄 요약, 추천 코멘트 |
| 인증 | **Auth.js (NextAuth)** | 이메일 + Google/카카오 소셜 |
| 결제(PG) | **토스페이먼츠** | 가상계좌·부분취소·정산 대시보드 활용 |
| 배포 | **Vercel** | Next.js 네이티브 |
| BaaS | **Supabase** | Postgres + pgvector + Storage 통합 |
| 스토리지 | **Supabase Storage** | 상품 이미지, E-ticket PDF |
| 이미지 최적화 | **next/image** | Supabase 원본 → WebP/리사이즈 |
| 이메일 | **Resend** _(잠정)_ | 예약 접수·확정·결제·E-ticket 안내 |
| 다국어 | **ko 단일** | 여권 필드만 영문 강제 (zod 검증) |
| 테스트 | **Vitest** | 결제/좌석 통합 테스트 핵심 경로만 |
| 관측 | **Vercel Logs**, Sentry는 결제 구현 직전 도입 | |
