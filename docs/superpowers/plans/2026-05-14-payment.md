# M-PAYMENT 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** 토스페이먼츠 v2 연동으로 `entities/payment` slice를 신설하여 **결제 승인(3-phase)·웹훅 멱등성·환불 보상 트랜잭션·금액 cross-check·이중 결제 방어**를 구현한다. 모든 구현은 `domain-booking.md` R3/R4/R6/R7/R8/R9 규칙을 명시적으로 따르고, 각 태스크 직후 `qa-engineer.md` R1·R3·R5·**R8(Plan 체크박스 파일 반영 검증)**을 반드시 자동 실행한다.

**Architecture:** `app/api/payments/{confirm,webhook/toss}` → `entities/payment` → `entities/booking.transitionStatus` → `entities/departure`(간접). Toss client는 `shared/lib/toss/`. 외부 IO는 모두 DB 트랜잭션 밖. PG 성공 + DB 실패 시 **`compensateCancel` 동기 호출 → 실패 시 `RefundJob` 큐 enqueue**로 자기 치유.

**Tech Stack:** Next.js 15 App Router, TypeScript strict, Prisma 5 + PostgreSQL, Zod 3, Vitest 2, Toss Payments v2

**Applied Personas:**
- 💳 `domain-booking` ⭐ — R3(2-phase), R4(웹훅 멱등성), R6(금액 정수), R7(보상 트랜잭션), R8(관측), R9(Toss 특이사항), R10(TDD)
- 🏛️ `architect` ⭐ — `entities/payment` slice + `shared/lib/toss/` 신설, barrel 명시 export, 단방향 의존성
- ⚙️ `backend-expert` — Prisma `$transaction` 경계, `$executeRaw` 안전, Zod 입력 검증, env 추가
- 🔬 `qa-engineer` — 매 태스크 자동 증거 수집 + **R8 Plan 체크박스 File-written 검증**

**Spec:** `docs/superpowers/specs/2026-05-14-payment-design.md`
