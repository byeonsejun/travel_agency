# 2026-05-22 — Review & Photo (리뷰 & 사진 후기)

> PRD §4.2 추가 기능. **COMPLETED booking 보유자만** 작성 가능한 별점·텍스트·사진 후기.
> 사용자 결정: **스키마 옵션 A(정규화 1:N)** + **업로드 옵션 1(Presigned URL)**.

## Context

- Booking 상태머신에 `COMPLETED` 존재 — 작성 자격 게이트로 사용.
- Supabase Storage `product-images` 버킷 생성 완료 (B1, 2026-05-21). 별도 버킷 신설 없이
  **같은 버킷 + path prefix `review-photos/<reviewId>/<idx>.<ext>`** 로 분리 — IAM/CORS/
  lifecycle 단일화로 운영 부담 절감.
- `env.ts` 에 `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY`
  자리 이미 존재(optional). 실제 값은 사용자가 Supabase 콘솔에서 수동 주입 필요.

- Vercel function payload 4.5MB 제한 회피 + 서버 stream-through 비용 0이 옵션 1 선택 이유.
- Orphan 파일 정리는 본 plan 범위 외 (Out of Scope, 별도 cron plan).

## Design Decisions

### 1. 데이터 모델 (옵션 A — 정규화 1:N)

```prisma
enum ReviewStatus {
  PUBLISHED   // 정상 노출
  HIDDEN      // 어드민 숨김 (모더레이션)
  REPORTED    // 사용자 신고 (모더레이션 대기)
}

model Review {
  id        String       @id @default(cuid())
  bookingId String       @unique  // 1 booking = 1 review (작성 자격 + 중복 방지)
  userId    String
  productId String
  rating    Int          // 1~5 (Zod min/max)
  content   String       @db.Text  // max 1000자
  status    ReviewStatus @default(PUBLISHED)
  createdAt DateTime     @default(now())
  updatedAt DateTime     @updatedAt

  booking Booking      @relation(fields: [bookingId], references: [id], onDelete: Cascade)
  user    User         @relation(fields: [userId], references: [id], onDelete: Cascade)
  product Product      @relation(fields: [productId], references: [id], onDelete: Cascade)
  photos  ReviewPhoto[]

  @@index([productId, status, createdAt(sort: Desc)])
  @@index([userId, createdAt(sort: Desc)])
}

model ReviewPhoto {
  id          String  @id @default(cuid())
  reviewId    String
  storagePath String  // "review-photos/<reviewId>/<idx>.<ext>"
  order       Int
  width       Int?
  height      Int?

  review Review @relation(fields: [reviewId], references: [id], onDelete: Cascade)

  @@unique([reviewId, order])
  @@index([reviewId])
}
```

User/Product/Booking 모델에는 `reviews Review[]` relation 추가. 모든 onDelete: Cascade — booking 삭제/user 탈퇴/product 제거 시 review·photo 자동 정리.

### 2. Storage path 컨벤션
- `review-photos/<reviewId>/<idx>.<ext>` — 같은 `product-images` 버킷 재사용 + path prefix 분리. 신규 버킷 없음.
- 확장자는 MIME 기반 매핑(jpeg→.jpg, png→.png, webp→.webp). 그 외 MIME 거부.

### 3. Supabase 클라이언트 위치 (shared)
- `src/shared/lib/supabase/server.ts` — `createServerSupabase()`: `SERVICE_ROLE_KEY` 로 init, **server-only**. env 미설정 시 throw(fail-fast).
- `src/shared/lib/supabase/storage.ts` — `createReviewPhotoSignedUploadUrl(pendingReviewId, idx, mime)`, `getReviewPhotoPublicUrl(path)`.

### 4. Upload 흐름 (Presigned URL, 4-step + Atomic 가드)

1. **사용자 폼에서 사진 선택 + rating + content 입력** → 제출 클릭
2. **Step 1 — `signReviewPhotoUploads`** Server Action:
   - `auth()` + `bookingId` 소유자·`COMPLETED` 게이트 + 중복 review 체크
   - `pendingReviewId = cuid()` 생성 (DB 행 만들지 않음, 클라이언트 임시 토큰)
   - `photoMetas[{idx, mime}]` 별로 `createSignedUploadUrl` 발급
   - 응답: `{ pendingReviewId, slots: [{idx, path, signedUrl, token}] }`
3. **Step 2 — 클라이언트 직접 업로드**: 각 `signedUrl` 로 병렬 PUT (multipart 아닌 raw binary). 실패한 슬롯은 알림 후 사용자에게 재시도.
4. **Step 3 — `submitReview`** Server Action:
   - `auth()` + 게이트 재확인
   - `pendingReviewId` 를 그대로 `Review.id` 로 사용 → **Review + ReviewPhoto[] 한 트랜잭션 create** (atomic)
   - `revalidatePath(/products/${productId})` + `revalidatePath(/mypage)`

**Atomic 가드 효과**: DB 행은 Step 3에서만 생성. Step 2 실패 시 Storage에 orphan 파일만 남고 DB 정합성 손상 0건. orphan은 추후 별도 cron 으로 정리(Out of Scope).

### 5. Server Action 시그니처

```ts
// features/review-upload/server/actions.ts
"use server";

signReviewPhotoUploads(input: {
  bookingId: string;
  photoMetas: Array<{ idx: number; mime: "image/jpeg" | "image/png" | "image/webp" }>;  // max 5
}): Promise<
  | { ok: true; pendingReviewId: string; slots: Array<{ idx; path; signedUrl; token }> }
  | { ok: false; error: "NOT_OWNER" | "NOT_COMPLETED" | "ALREADY_REVIEWED" | "INVALID" }
>;

submitReview(input: {
  pendingReviewId: string;
  bookingId: string;
  rating: number;     // 1~5
  content: string;    // 1~1000
  paths: Array<{ path: string; order: number; width?: number; height?: number }>;  // max 5
}): Promise<
  | { ok: true; reviewId: string }
  | { ok: false; error: "NOT_OWNER" | "NOT_COMPLETED" | "ALREADY_REVIEWED" | "INVALID" }
>;
```

두 액션 모두 Zod 가드 + `auth()` + Booking 소유자·`COMPLETED` 검증. discriminated union 반환으로 클라이언트가 에러를 명시적으로 처리.
