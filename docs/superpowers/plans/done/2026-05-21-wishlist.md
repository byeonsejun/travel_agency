# 2026-05-21 — Wishlist (찜하기)

> PRD §4.2 추가 기능 후보 「위시리스트」 구현. 구매 전환의 허들을 낮추기 위한 **순수한 즐겨찾기** 만 도입 — 가격/좌석 변동 알림(체리피킹 유발 우려)은 의도적으로 제외.

## Context

- 현재 PDP/카드에는 "예약하기" CTA 만 있고, "관심 표시 후 나중에 돌아오기" 동선이 없음.
- NextAuth v5 세션은 이미 구비 (`auth()` 헬퍼).
- `/mypage` 는 프로필 / 여권 정보 / 예약 내역 3섹션으로 구성 — 같은 page 안에 "찜한 상품" 섹션을 추가하는 형태가 일관성·발견성 면에서 자연스러움.
- 비로그인 유저 동선: **하트 클릭 → `/login?callbackUrl=...&wishlistAddPending=<productId>` → 로그인 후 callbackUrl 페이지가 RSC에서 자동 add → 쿼리 제거 redirect.** (사용자 결정 — 옵션 1)

## Design Decisions

1. **데이터 모델**: `Wishlist(id, userId, productId, createdAt)` + `@@unique([userId, productId])` 로 중복 방지. `@@index([userId, createdAt(sort: Desc)])` 로 마이페이지 최신순 정렬 인덱스. `User` / `Product` 양쪽에 relation 추가.
2. **Cascade 정책**: `onDelete: Cascade` — 유저나 상품이 삭제되면 wishlist 행도 자동 제거. wishlist는 파생 데이터이므로 보존 가치 없음.
3. **Server Action 시그니처**: `toggleWishlistAction(formData)` — `productId` + `returnTo` 두 hidden input 만 받음. Zod로 productId(min 1), returnTo(`startsWith("/")` open-redirect 가드).
4. **비로그인 처리 (옵션 1) — API route 방식**:
   - Action 진입 시 `auth()` 미세션 → `redirect("/login?callbackUrl=/api/wishlist/resume?productId=...&returnTo=...")`.
   - 로그인 성공 후 `/api/wishlist/resume` route handler 가 `db.wishlist.upsert` (add-only, idempotent) 처리 → `returnTo` 로 redirect.
   - **별도 API route 인 이유**: RSC 헬퍼로 처리하면 페이지가 `searchParams` 의존이 되어 PDP/홈의 ISR 정책(`revalidate = 3600` 등)이 dynamic 으로 떨어진다. route handler 는 그 영향 없음.
5. **Heart Button**: `'use client'`. `useOptimistic` 으로 즉시 하트 색 반전, `useTransition` 으로 pending 상태 disable. form 내부 hidden input(`productId`, `returnTo`) + `submit` 버튼.
6. **inWishlist 사전 계산**: 상품 목록 RSC에서 한 번에 `getMyWishlistProductIds(userId)` 호출 → `Set<string>` 반환 → 각 카드에 `inWishlist={ids.has(p.id)}` props 주입. **N+1 차단.**
7. **혼합 RSC/CC**: ProductCard 는 RSC 유지. WishlistHeartButton 만 `'use client'` 자식으로 박힘 — RSC island 패턴.
8. **revalidate 범위**: action 성공 후 `revalidatePath(returnTo)` — 같은 페이지를 다시 SSR해서 최신 상태로 동기화. `/mypage` 위시리스트 섹션은 자체 페이지 revalidate.
9. **마이페이지 통합**: 별도 라우트가 아닌 `/mypage` 내부 새 섹션. 예약 내역 위에 배치(즐겨찾기 → 예약 자연 흐름). 카드는 작은 그리드 (`grid-cols-2 sm:grid-cols-3`) + 각 카드에 하트 토글(제거 가능).
10. **TDD 범위**: `entities/wishlist/model/safeReturnTo.ts` (open-redirect 가드 순수 함수) + `entities/wishlist/api/queries.ts` 의 핵심 로직은 단위 테스트. UI는 SSR 렌더 테스트로 보강(use client 컴포넌트 자체는 통합 테스트 어려우므로 행동 가능한 최소 케이스만).
