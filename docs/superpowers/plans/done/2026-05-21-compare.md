# 2026-05-21 — Compare Mode (상품 비교)

> PRD §4.2 추가 기능 「상품 비교 모드 (2~3개 나란히)」 구현.
> 사용자 결정: **URL search params 단일 진실 원천** + **최대 3개**. 공유 가능
> URL/새로고침 보존/SSR 친화가 핵심.

- PRD §4.2: "상품 비교 모드 (2~3개 나란히)". 정량 비교 항목 — 가격·기간·
  목적지·태그·포함/불포함.

  hydration·SSR 격리 부담이 큼.

## Design Decisions

1. **URL 스키마**: `?compareIds=id1,id2,id3` 쉼표 구분. 최대 3개 강제. 다른 쿼리(sort/destination/page 등)와 자유롭게 공존.
2. **순수 함수 (TDD)** — `features/product-compare/model/compareIds.ts`:
   - `MAX_COMPARE = 3`
   - `parseCompareIds(raw: string | string[] | undefined): string[]`
   - `serializeCompareIds(ids: string[]): string` (빈 배열은 빈 문자열 → 호출자가 URL 에서 키 자체 제거)
   - `addCompareId(arr, id)`: 이미 있으면 no-op, 3개 가득이면 거부(no-op), 새 id 는 push.
   - `removeCompareId(arr, id)`
   - `isInCompare(arr, id): boolean`
3. **CompareToggleButton (`'use client'`)**: `useRouter().replace()` + `useSearchParams()` 로 URL 토글. `useTransition` 으로 pending 처리. 가득 차고 미선택 상태면 `disabled` + `title="최대 3개까지"`.
4. **FloatingCompareCart (`'use client'`)**: `useSearchParams` 로 `compareIds` 읽기. **0개면 미렌더**. 1~3개면 sticky bottom bar (mobile-first) — 썸네일 슬롯 N개 + 각 슬롯 X(제거) + "비교하러 가기 (N)" CTA(`Link href="/compare?compareIds=..."`).
5. **ProductCard Link 보존 (cross-page 상태 보존)**: 카드 클릭 → PDP 이동 시 현재 `compareIds` 가 함께 따라가야 함. ProductCard 에 `linkQueryString?: string` props 추가 → `href={`/products/${id}${linkQueryString ? "?" + linkQueryString : ""}`}` 합성. 부모(ProductCardList) 가 page 에서 받은 currentCompareIds 로 빌드.
6. **PDP 의 compareIds 인지**: `/products/[id]` 가 `searchParams.compareIds` 받기 → 자체 토글 버튼 표시 + `<FloatingCompareCart />` 렌더. PDP 내부에서 토글하면 자기 자신 URL 의 compareIds 만 갱신.
7. **`/compare` RSC**: `searchParams.compareIds` → `parseCompareIds` → Zod (각 id 는 cuid 형식) → `getProductsByIds(ids.slice(0, 3))`. 0개 → EmptyState. 1~3개 → `<ProductCompareTable />`. **searchParams 의존이므로 자연스럽게 dynamic — `export const dynamic`/`revalidate` 미지정.**
8. **ProductCompareTable (RSC)**: 데스크탑은 가로 표(컬럼=상품), 모바일은 상품별 카드 세로 stack. "비교에서 빼기" 헤더 액션은 다시 `'use client'` 컴포넌트(`CompareRemoveButton`) — `/compare` 페이지의 URL 갱신.
9. **ProductCard 슬롯 통합**: 기존 `heart?: ReactNode` 와 같은 방식으로 `compareButton?: ReactNode` 슬롯 신규 추가. 두 슬롯 모두 features/product-compare/wishlist 의존성을 ProductCard 가 직접 가지지 않도록 의존성 역전 유지 (vitest module-graph 오염 방지 — wishlist 작업 시 검증된 패턴).

  - `parseCompareIds("a")` → `["a"]`
  - `parseCompareIds("a,b,c")` → `["a","b","c"]`
  - `parseCompareIds("a,b,c,d")` → `["a","b","c"]` (MAX_COMPARE clamp)

  - `addCompareId(["a","b","c"], "d")` → `["a","b","c"]` (MAX 도달, no-op)
  - `addCompareId(["a","b"], "a")` → `["a","b"]` (중복, no-op)
  - `removeCompareId(["a","b","c"], "b")` → `["a","c"]`
  - `removeCompareId(["a"], "z")` → `["a"]` (없는 id, no-op)
  - `serializeCompareIds([])` → `""`
  - `serializeCompareIds(["a","b"])` → `"a,b"`
  - `isInCompare(["a","b"], "b")` → `true`
