# M-BOOKING 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use `superpowers:subagent-driven-development` (recommended) or `superpowers:executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** `entities/booking` slice를 신설하여 좌석 lock·8단계 상태머신·트랜잭션·BookingEvent append-only 로그를 도입한다. 모든 구현은 `domain-booking.md` 규칙을 명시적으로 따르고, 각 태스크 직후 `qa-engineer.md`의 자동 증거 수집(로그·테스트 출력·DB 조회)으로 검증한다.

**Architecture:** 8단계 상태머신(`RECEIVED → AWAITING_GROUP → DEPARTURE_CONFIRMED → PAID → READY → COMPLETED` + `CANCELED_BY_*`). 좌석 차감은 **raw SQL compare-and-set**(Prisma `updateMany`는 `capacity >= bookedSeats + n` 비교 미지원). 모든 상태 전이는 `transitionStatus` 단일 진입점 + `BookingEvent` append.

**Tech Stack:** Next.js 15 App Router, TypeScript, Prisma 5 + PostgreSQL, Zod 3, Vitest 2

**Applied Personas:**
- 💳 `domain-booking` — R1(좌석 CAS), R2(좌석 hold/TTL은 M-PAYMENT 위임), R5(상태 화이트리스트), R6(돈은 Int), R7(보상 트랜잭션 hand-off), R8(BookingEvent), R10(TDD)
- 🏛️ `architect` — entities/booking slice 신설, barrel, 단방향 의존성
- ⚙️ `backend-expert` — Prisma `$transaction`, `$executeRaw` 안전, select 명시
- 🔬 `qa-engineer` — 각 태스크 직후 자동 증거 수집 + Evidence-first 보고

**Spec:** `docs/superpowers/specs/2026-05-14-booking-design.md`
