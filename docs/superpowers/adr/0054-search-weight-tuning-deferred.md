# ADR-0054: 검색 가중치 튜닝 보류 — 작은 카탈로그의 변별력 측정 우선

- **상태**: Accepted
- **결정일**: 2026-06-14
- **영향 범위**: `scripts/search-eval/`, `src/entities/product/model/searchWeights.ts`(미변경)
- **관련 commit**: `124d4e3` (discrimination expansion — 45-query catalog + LLM-as-judge labels), 인접 [ADR-0049] / [ADR-0050]

## Context (배경)

검색 점수는 `vector 0.5 / keyword 0.2 / geo 0.2 / theme 0.1` 4축 가중합이고, 이 값은 3곳에 미러된다(`searchWeights` 상수 · SQL `buildThemeScore` · eval `scoreReplica`). [ADR-0049]에서 nDCG eval 하네스를 도입했으나, golden 10쿼리는 nDCG가 포화(다수 1.000)되어 가중치 우열을 변별하지 못했다. "더 나은 가중치가 있는데 게을러서 안 바꾸는 것"인지, "현행이 실제로 합당"한지 — 측정 도구가 답을 못 주던 상태.

## Decision (결정)

**가중치를 튜닝하지 않는다(SSOT 3중 미러 미변경).** 대신 변별력을 *측정*하는 하네스를 확장한다: 코퍼스(20건 불변)가 실제 지지하는 차원만 자극하는 45쿼리 카탈로그를 5개 아키타입(pure-semantic 9 / geo-dominant 8 / theme-dominant 11 / constraint 7 / adversarial 10)으로 분배하고, 라벨은 LLM-judge로 생성([ADR-0055]), `--catalog` 모드로 baseline 순위·sweep 스프레드·과적합(vector≤0.1) 지표를 본다.

확장 후 변별력 델타(commit `124d4e3` 본문):

```
top 동률 중 vector≤0.1 : 4 → 0      (벡터 굶긴 설정이 최고점 공유하던 과적합 해소)
baseline 순위          : 64/286 → 120/286
pure-semantic 슬라이스 : 0.61        (벡터 약점이 비로소 노출됨)
```

## Consequences (결과)

**얻은 것:**
- 가중치 변경의 근거가 "직관"이 아니라 측정치가 됨 — 286 격자 sweep에서 현행이 어디에 있는지(120/286) 정량 확인.
- 과적합 신호 가시화: 벡터를 굶긴 설정이 작은 라벨셋에서 최고점을 "동률"로 공유하던 현상(4건)이 카탈로그 확장으로 0건이 됨 → "sweep 1등을 따라가면 안 되는" 이유가 데이터로 드러남.
- 런타임/도메인 0줄 변경 — 측정 하네스(`scripts/search-eval/`)만 확장.

**포기한 것 / 미해결:**
- 코퍼스 20상품 = 카탈로그 전체라는 제약. 실 트래픽 쿼리 분포와 다를 수 있음(대표성 한계). 20건을 넘는 코퍼스 확장은 임베딩 재추출 비용이 들어 보류.
- pure-semantic 0.61이 드러낸 "벡터 약점"은 *측정*만 됐고 *교정*은 안 함(튜닝 보류 결정의 직접 귀결).

## Alternatives Considered (대안 — 가장 중요한 섹션)

### 옵션 A: sweep 1등 가중치로 운영 전환 (예: vector를 0.1로 낮춘 설정)
- 286 격자 sweep의 최상위 점수 설정으로 즉시 교체.
- **거부.** (1) golden 10쿼리/카탈로그 20코퍼스는 라벨셋이 작아 1등의 이득이 측정 노이즈에 묻힌다([ADR-0049]: +0.0099, 상대 1.1%). (2) 확장 전 top 동률 4건이 *모두 벡터를 굶긴(vector≤0.1)* 방향이었고, 카탈로그 확장 후 이 동률이 0으로 사라짐 — 즉 "1등"은 작은 셋에 과적합된 신호였다. 의미 벡터(의미 유사도)를 낮추는 건 미지의 신규 쿼리에서 오히려 손해.

### 옵션 B: 실 트래픽 로그를 모은 뒤 온라인 지표로 튜닝
- 실제 사용자 클릭/전환 기반으로 가중치 최적화.
- **보류(거부 아님).** 라이브 서비스·트래픽이 없어 현재 불가([NO-REAL-MONEY] 제약 하의 데모 단계). 트래픽이 생기면 이 옵션이 옳은 경로 → 이 ADR을 supersede 후보로 남김.

## Notes

- 가중치를 바꾸려면 반드시 3중 미러(`searchWeights` 상수 / SQL `buildThemeScore` / eval `scoreReplica`)를 동시 갱신해야 한다(드리프트 가드).
- 코퍼스가 20건을 넘게 확장되면 "20=카탈로그 전체" 전제가 깨지므로 본 ADR의 대표성 한계 항목을 재검토할 것.
- 측정만 하고 교정 안 한 pure-semantic 0.61은 코퍼스 확장 시 가장 먼저 다시 볼 지표.
